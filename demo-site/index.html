Record, evaluate, compare - and catch what a pass/fail number hides

AIRE is a trace-based evaluation framework for LLM/RAG systems. Every invocation is recorded as a validated trace; deterministic metrics and a failure taxonomy score the records; a regression engine compares versions metric-by-metric with per-case attribution. This explorer renders the committed evaluation of a small RAG system - three deterministic versions plus one recorded live-LLM run.

What the evaluator caught in 60 seconds: version 3 reads better and retrieves better (recall 0.73 → 0.91) but silently drops every citation - groundedness 0.57 → 0.00 across 22 ungrounded cases, flagged automatically as a regression. The live-LLM run then fixes abstention (0.0 → 1.0) and grounding (1.0) at the price of 15 s/case and ~605 tokens/case. No single number tells this story; the metric set does.

Explore a run

Aggregate metrics first, then per-case evidence: open any case to see the recorded answer, citations, retrieved documents, spans and token usage. Evaluation reads traces - the system is never re-run.

Regression comparisons

Direction-aware relative thresholds (higher-better vs lower-better), with every regression attributed to the cases that moved. Verdicts come from the committed comparison reports.

Data: committed evaluations from results/ in github.com/vaibhav3000/aire, rendered by demo-site/build.py. Deterministic runs are offline and exactly reproducible (python demo/run_demo.py); the live-LLM run is recorded separately and is nondeterministic by declaration. Groundedness is a lexical citation-overlap proxy - it measures citation hygiene, not semantic faithfulness (documented in the README's Limitations).
