\title{AIRE: AI Reliability \& Evaluation Engine\\
\large Replayable Trace-Based Evaluation and Regression Testing for LLM and RAG Systems}

\author{\IEEEauthorblockN{Vaibhav Mahore}
\IEEEauthorblockA{\textit{Undergraduate Programme, Mathematics and Computing}\\ \textit{Indian Institute of Science (IISc), Bengaluru, India}\\ mvaibhav@iisc.ac.in}}

\maketitle

\begin{abstract}
Evaluating large language model (LLM) applications differs fundamentally from
testing conventional software: outputs are nondeterministic, no single
correct answer exists for most prompts, every evaluation may incur API cost,
and model behavior drifts under the provider's control. This paper presents
AIRE (AI Reliability \& Evaluation Engine), a system that separates system
execution from system evaluation. A system under test (SUT) is invoked once
per case; each invocation is recorded as a validated, schema-constrained
trace (answer, retrieved documents, one timed span per attempt, token usage
with explicit source labeling, errors). All downstream analysis (17
deterministic per-case metrics, a failure taxonomy checked in pipeline
order, and a direction-aware regression gate with per-case attribution)
operates on the stored traces and never re-runs the system. On a 26-case
retrieval-augmented-generation (RAG) suite over a 12-document corpus with
three deterministic SUT versions, the gate blocks an intentional ``fluent
but uncited'' regression (lexical groundedness 1.00 to 0.00, gold citation
recall 0.73 to 0.00, 20 cases newly ungrounded) and attributes a retrieval
gain (recall@3 0.73 to 0.91) to retrieving three documents instead of one
rather than to the retriever's weighting. The paper also reports what an
audit of the evaluator found: a citation-segmentation bug that had scored
verbatim quotes as half grounded, failed calls counted as correct
abstentions, and a gate that ignored metrics missing from the candidate.
These defects had shaped the headline numbers of an earlier live-LLM run,
which is therefore reported as historical and not replayable. AIRE's
groundedness metric is a lexical citation-overlap proxy, not semantic
entailment, and its deterministic responder is a reproducible harness rather
than a language model.
\end{abstract}

\section{Introduction}
Testing an LLM application with conventional assertions fails for five
reasons. (1) \emph{Nondeterminism}: identical prompts can yield different,
equally acceptable answers. (2) \emph{Absence of an oracle}: most prompts
have no single correct output, so equality assertions are inapplicable.
(3) \emph{Cost and latency}: every evaluation step may be a billable API
call taking seconds. (4) \emph{Drift}: providers may change model behavior
behind a stable model name. (5) \emph{Hidden failure modes}: a system can be
confidently wrong (hallucination) or right for unsupported reasons
(ungrounded), neither of which an \texttt{assert} detects.

The practical consequence is that teams change a prompt, a retriever, or a
model and cannot say systematically what improved or regressed. AIRE
addresses this with one design decision: \emph{run the system once, store
validated traces, and perform all evaluation and comparison on the stored
records}. Evaluation thereby becomes replayable (new metrics run at zero
API cost), fair (both versions are scored on identical stored outputs),
auditable (every score is traceable to a recorded answer and its evidence),
and safe from silent re-execution, which would inject nondeterminism into
the comparison itself.

This paper's contributions are: (1) a trace schema and crash-safe storage
format with write-time validation (Section~III); (2) a suite of 17
deterministic per-case metrics spanning answer quality, citation behavior,
abstention, retrieval at fixed cut-offs, tool use, cost and reliability
(Section~IV); (3) a failure taxonomy ordered by pipeline stage and a
direction-aware regression gate that refuses incomparable runs and treats a
vanished metric as a regression (Section~V); (4) a controlled three-version
RAG demonstration with an intentional quality regression and a retrieval
ablation (Section~VI); and (5) an account of the evaluator's own defects,
how they distorted earlier results, and how they were fixed (Section~VII).

\section{System Overview}
AIRE's pipeline separates execution from evaluation (Fig.~\ref{fig:pipe}).
The upper path runs once: an evaluation dataset (JSONL, one case per line)
drives a SUT; each invocation is wrapped into a \emph{Trace} by the runner,
which adds timeout enforcement, bounded retries and untimed client-side
pacing. The lower path is pure computation over stored records: the
evaluation engine computes per-case metrics and aggregate statistics, the
failure classifier assigns each case at most one category, and the
regression engine compares two evaluated runs. Reports are static,
self-contained HTML files.

\section{Trace Model and Replayability}
A trace is the complete record of one invocation: \texttt{run\_id},
\texttt{case\_id}, the SUT configuration fingerprint, the final answer, the
list of retrieved document identifiers, tool calls, an ordered list of timed
spans (kind, name, latency, attributes, error), token usage, an error field,
a unique trace identifier and a schema version. Four design rules govern it.

\textbf{Write-time validation.} Every trace is checked against the schema
at append time (required identifiers present, non-negative span latencies
and token counts, tool calls as named objects, one trace per case);
invalid traces fail loudly rather than corrupting a run, so all downstream
components may trust stored data. The dataset loader is equally strict:
unknown fields and non-boolean flags are errors, not silently dropped.

\textbf{Honest timing and usage.} The runner records one span per attempt,
failed attempts included. Client-side pacing runs before the timer, and
waits the system reports (rate-limit backoff between provider retries) are
recorded on the span and subtracted from its latency. Token counts carry a
\texttt{token\_source} label: \texttt{heuristic} (a length-based estimate)
for local systems, \texttt{api} when the provider reports real counts, and
\texttt{none} for failed calls, which are never filled with an estimate.

\textbf{Crash safety.} Each trace is appended and synced to disk as soon as
its case finishes, so an interrupted run keeps every completed case;
manifests and results are written through a temporary file and an atomic
rename. Stored traces are never rewritten.

\textbf{Run identity.} The manifest pins the dataset (SHA-256 and a path
relative to the repository), a corpus hash, the SUT configuration and
whether the SUT declares itself deterministic. The regression engine
refuses to compare runs over different datasets or case sets.

\subsection{Lexical Groundedness: Definition and Limits}
Groundedness splits the answer into claims at sentence terminators and line
breaks. Citations written directly after a terminator belong to the
sentence before them (``S1.\ [doc:x] S2.'' cites S1), following the
convention that a citation follows the claim it supports. A claim is
supported when at least half of its content keywords appear in a document
it cites \emph{that the system retrieved}; citing a document outside the
retrieved context cannot ground a claim. Uncited claims count as
unsupported. The score is supported claims over claims with content;
abstentions return no value.

This is deliberately a \emph{lexical proxy}, not semantic entailment. A
false positive is possible: an invented sentence that reuses the source
document's vocabulary can pass, and at the default threshold a sentence
that is half invented passes. A false negative is possible: a correct
paraphrase with non-overlapping vocabulary scores zero. The proxy's value
is that it is deterministic, cheap, auditable, and enforces citation
discipline; replacing it with an entailment model is a documented
extension, and the metric's contract is that its number is never presented
as truthfulness.

\subsection{Failure Taxonomy}
Each non-success case receives exactly one category, checked in pipeline
order so a failure is blamed on its earliest cause:
\emph{invocation\_error} (the call failed or produced no answer),
\emph{missed\_abstention} (answered an unanswerable case),
\emph{retrieval\_miss} (a supporting document is missing from the top 3),
\emph{tool\_error}, \emph{wrong\_abstention} (refused although the
supporting documents were retrieved), \emph{ungrounded} (groundedness below
0.5), \emph{incomplete\_answer} (keyword recall below 0.5), and
\emph{answer\_mismatch}. Checking retrieval before answer quality matters:
under the earlier order, which checked retrieval last, five of the nine
incomplete answers of the baseline were in fact retrieval misses.

\section{Regression Engine}
Comparing runs A (baseline) and B (candidate) first checks that they
evaluated the same dataset and case set. Each mean metric $m$ and the
success rate are then compared with a direction from a metric registry
(latency, tokens, cost, errors and false refusals are lower-is-better).
With $b_m$ and $c_m$ the baseline and candidate means, the change is
absolute for scores in $[0,1]$ and relative for unbounded metrics, falling
back to absolute at a zero baseline:
\begin{equation}
\Delta_m = \begin{cases}
c_m - b_m & \text{if } m \text{ is bounded or } b_m = 0,\\
(c_m - b_m)/|b_m| & \text{otherwise,}
\end{cases}
\label{eq:delta}
\end{equation}
and $m$ is \emph{regressed} or \emph{improved} when $\Delta_m$ crosses a
tolerance $\tau$ (default 0.02) against its direction. A metric present in
the baseline but absent from the candidate is a regression, so a broken
candidate cannot pass by producing fewer metrics; a mean over a different
number of cases is flagged; and token means from different token sources
receive no verdict. Every regressed metric carries per-case attribution
under the same rule as \eqref{eq:delta}. The command-line gate exits 1 on a
regression and 2 on unusable inputs, so a crash is never mistaken for a
blocked regression. In continuous integration the gate compares freshly
generated runs against the committed results and fails on any drift of the
generated artifacts.

\section{Experiments}

\subsection{Setup}
The benchmark consists of a 12-document corpus for a fictional cloud
provider (covering refunds, rate limits, SLA credits, data retention,
encryption, onboarding, billing, status, support tiers, export, regions,
compliance) and 26 evaluation cases: 20 answerable from a single document,
2 answerable from a pair, and 4 plausible but unanswerable questions.

Three deterministic SUT versions are evaluated: \textbf{v1} (keyword
overlap scoring, top-1 retrieval) extracts and cites the best sentences;
\textbf{v2} switches to IDF-weighted scoring and retrieves the top 3
documents; \textbf{v3} keeps v2's retrieval but merges the extracted
sentences into one and drops the citations, an intentional regression in
grounding. The deterministic responder is a harness, not a language model:
it exists so that every committed number is exactly reproducible and
evaluator bugs surface as metric changes rather than hiding in model noise.

\subsection{Deterministic Results}
Table~\ref{tab:versions} shows per-version aggregates over the 26 cases.
v2 versus v1 passes the gate (3 metrics improved, 11 neutral, none
regressed): recall@3 rises from 0.7273 to 0.9091, MRR@3 from 0.7727 to
0.8333 and the success rate from 0.4615 to 0.5000, while recall@1 is
unchanged. The ablation in Table~\ref{tab:ablation} holds the cut-off fixed
and varies only the weighting: at $k=3$ plain overlap recalls 0.9545 of the
supporting documents and IDF 0.9091, so the v1 to v2 gain comes from
retrieving more documents, not from IDF.

v3 versus v1 is the central demonstration: the gate blocks it because
groundedness falls from 1.0000 to 0.0000, gold citation recall from 0.7273
to 0.0000 and the success rate from 0.4615 to 0.0000, and citation
precision disappears because nothing is cited. Retrieval matches v2. The
failure taxonomy localizes the damage: 20 cases become ungrounded. Latency
is reported but excluded from verdicts, because sub-millisecond timings of
the offline harness are noise.

A second finding is a genuine capability boundary: abstention correctness
is 0.0 for every version. With IDF weighting the top retrieval scores of
the unanswerable queries range from 0.18 to 0.46, while answerable queries
go as low as 0.19, so any threshold that rejects every unanswerable query
also rejects answerable ones. The limitation is documented as requiring
semantic matching rather than patched with an unprincipled cutoff.

\subsection{A Historical Live LLM Run}
An earlier version of the system ran the same suite once with a real
generator (Gemini 2.5 Flash at temperature 0 over the same retriever).
That run was scored with the metric code before the fixes in
Section~VII, and its traces were not kept, so it cannot be re-scored; its
committed numbers are shown in Table~\ref{tab:live} only as a record of
what was reported. Seventeen of 26 cases completed cleanly, six failed with
HTTP 429 quota errors and one answerable case was refused. The model
answered ``I don't know.'' on all four unanswerable cases. The other
headline differences do not survive scrutiny: the groundedness of 1.0
averaged only the 15 cases that produced a claim, against a baseline the
segmentation bug had pushed down to 0.5682; the 15.3\,s mean latency
included the client's own pacing and retry sleeps; and the token comparison
set API counts (with heuristic estimates for the failed calls) against a
character estimate for a system that makes no LLM call. The current script
persists traces and supports re-scoring, so a new run will be replayable.

\section{Engineering Lessons}
Several defects surfaced in the evaluator itself, and an adversarial audit
found more; each is now fixed and covered by a test or a CI check. (1) Citation segmentation split
answers after every period, so a citation written after the period moved
to the next sentence and verbatim quotes scored 0.5; an earlier write-up of
this project described the bug as fixed when only the trailing case was.
(2) A failed or empty invocation counted as a correct abstention on
unanswerable cases and dropped out of groundedness, so a candidate whose
calls crashed could look better. (3) The gate silently skipped metrics
missing from either run, compared relative changes on bounded scores, and
treated a crash (exit 1) like a blocked regression. (4) Continuous
integration regenerated baseline and candidate from the same commit, so a
change that moved every version equally passed. (5) Measured LLM latency
included the client's pacing and backoff, and the provider retried
non-retryable client errors. (6) Unordered set iteration made committed
aggregates change with the interpreter's hash seed. Two operational lessons
from the live run remain: provider errors must propagate into the trace's
error field rather than appear as empty answers, and a 30-second invocation
watchdog that cut off 14 of 26 thinking-mode generations showed that
reliability parameters are part of the system under test.

\section{Limitations}
(1) The groundedness metric is a lexical proxy and can be fooled in both
directions. (2) The gate is a change detector, not a statistical test: its
default tolerance of 0.02 is small next to the sampling noise of a mean
over 22 cases (one case moving by 0.44 shifts the mean past it), there are
no repeated runs, confidence intervals or paired tests, and the thresholds
were chosen on the same 26 cases they gate. That suits a deterministic
system; gating an LLM would need tolerances above the run-to-run spread
measured over several runs. (3) Keyword retrieval cannot decide
answerability, and abstention rests on four cases. (4) The deterministic
responder is a rule-based harness; it bounds what deterministic results can
say about real LLM behavior. (5) Heuristic token counts are approximations
by design, and the cost metric uses a zero default price. (6) The corpus
and case count are deliberately small; the machinery (dataset and corpus
hashing, run identity checks, attribution) is designed to scale but is not
demonstrated at scale here.

\section{Conclusion}
AIRE treats AI-system evaluation as a data problem: record validated traces
once, compute deterministic metrics, classify failures in pipeline order,
and compare runs with direction-aware tolerances, run identity checks and
per-case attribution. The three-version demonstration shows the gate
blocking a regression (groundedness 1.00 to 0.00) that keeps retrieval
intact, and the retrieval ablation shows the same machinery assigning an
apparent improvement to its real cause. The evaluator's own defects, and
the misleading live-LLM numbers they produced, are reported as part of the
result. Code, committed result files, and reports are available in the
accompanying repository.\footnote{\url{https://github.com/vaibhav3000/aire}}
